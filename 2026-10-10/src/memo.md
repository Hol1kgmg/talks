# このPJ（キーボード）の技術選定についてレビューしてください

2026/10/10 新卒N年目の勉強会&交流会！#6（7分）
https://fresh-engineers.connpass.com/event/405844/

## 対象

- 自作キーボード（ハードウェア）に興味はあるが、ハードルを感じているライト層
- ITエンジニア。技術選定・レビューの作法は共通言語として通じる前提

## 目的（聴衆に知ってもらう2点）

1. **キーボードの特徴が、こだわりにつながる**
   「こだわり」は感覚ではなく、製品の特徴として指させる。だから探せるし、買える
2. **こだわりを持つと、どんなメリットがあるか**
   どの環境でも理想の入力環境を持ち続けられる。キーボードは自分で選定できる唯一のレイヤー

この2点がそれぞれスライド6・7に対応し、構成の中心になる。

## こだわりの定義（自分の場合）

- キーボード入力をストレスなく、楽しいと思えること
- それを実現する製品の特徴が3つある: 形状・サイズ・配列
- メリット: プライベート / オフィシャル、OS、ソフトウェアに関係なく、自分の理想の環境を持ち続けられること

## 結論

### 主結論

**キーボードは、自分で選定できる唯一のレイヤー**

- 職場のPC・OS・エディタ・ツールは会社や案件で決まり、技術選定の多くは自分の裁量外
- キーボードだけは自分で要件を決め、自分で選定し、どの環境にも持ち込める

### 副結論（ライト層への背中押し）

- こだわりとは、選ばなかった理由を説明できること（ADRの不採用理由と同じ）
- こだわりは最初から無い。選ぶと生えてくる
- こだわりは全部でなくていい。1箇所でいい。1箇所とは製品選定そのもの

### 持ち帰りの一文（候補）

- 自作キーボードは、買える。選ぶところから始めればいい
- 会社の技術選定には口を出せないが、キーボードの選定は全部自分で決められる

## 着地点（ネクストアクション）

- サイズを試すなら、40%の完成品を1台買う。カスタム（スイッチ交換、キーマップ設定等）は選定に入れない
- 企業が完成品として自作キーボードを販売しているため、組み立て・部品購入なしで始められる。学習コストは「完成品があるから低い」の1行で済ませる
- 「自作キーボード」の定義を「組み立てるもの」から「自分で選定したもの」に置き換える

## 伝え方の方針

- 型: 技術選定レビューの体裁。見出しに「選定理由」「推奨」などの項目名を使って章立て感を出す。承認依頼サマリー等の稟議演出はスライドには入れない（薄い演出に留める）
- 語り口: 本人は大真面目。ギャグはスライドに入れず内容の落差に任せる
- 聴衆の役割: レビュアー。冒頭の「技術選定していますか？」で問いかけ、まとめで問い返す
- 流れ: 問いかけ（技術選定していますか）→ 具体（私のプロダクト）→ 分類（形状・サイズ・配列）→ 絞る（サイズ）→ 選定理由（40%）→ 行動（おすすめの1台）→ 抽象（メリット）→ まとめ
- 形状・配列は扱わない。「懇親会で聞きに来てください」に逃がす
- section スライドは入れない

### スライド11: 40%サイズの技術選定

見出しは章名「40%サイズの技術選定」。本文に目的（業務効率化）を最上段に置き、解（40%サイズ）まで一直線に分解して見せる。キーボードの図・画像は使わず、テキストと記号だけで抽象的に表現する。クリックは2回: 初期表示は「業務効率化」のみを画面の上下中央に置く。1クリック目で下の段が高さ0から伸びて（`grid-rows-[0fr]` → `[1fr]` を `transition-all` で遷移）、「業務効率化」が上へなだらかに動きながら2段目、1.2秒遅れて3段目が順に現れる。2クリック目で結論の枠が出る（`clicks: 2` + `v-click="2"`）。

```
# 40%サイズの技術選定

                業務効率化
                    ↓
          「入力する」動作に専念する
                    ↓
  「入力する」から「探す」に動作を切り替えないこと


      その結果、全てのキーがホームポジションの隣にある
              40%サイズを選定するに至った
```

- 上3段は目的 / 要求 / 要件の分解を `↓` で結ぶ。解は矢印で繋がず、余白を空けて最下部に角丸の枠（`border-2 border-sky-200`、背景の水色と同系で主張しない）で囲った結論文として置く（太字にはしない、サイズは `text-2xl`。文言は「その結果、〜を選定するに至った」）。分解と結論を見た目で区別する
- 関係語（「そのために」「ストレスとは」等）は書かない。繋ぎは上3段の縦の `↓` のみ
- 目的 / 要求 / 要件 のラベルは置かない（文の横に付けると不格好になるため削除）。階層は文字サイズと全体の中央寄せで示す
- 結論文の表現: 「指が届く」は手を動かせば100%でも成立するので不可。「ホームポジションの隣にある」は製品側の性質として言えて、1キー分の距離（上下左右・斜め含む）が具体的。ライト層向けなので斜めの厳密さは問わない
- 本筋以外はスライドに出さず、発表者ノート（HTMLコメント）に残して口頭で補う:
  - 探す → 視線が落ちる → 入力が止まる → 効率が落ちる
  - +α: 動作の切り替えで生まれるストレスも消える
  - 「動作の切り替え」=コンテキストスイッチ
- 旧11b「満たすサイズは、40%だけ」は結論文に吸収したため削除
- 実装: `layout: default` に HTML + UnoCSS ベタ書き（`flex flex-col text-center`）。新コンポーネントは作らない
